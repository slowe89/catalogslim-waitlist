# CatalogSlim — polish fixes for Grok Build

**Grade: FAIL**

This is the least finished of the four snapshots. The confirmation cannot become visible with the current CSS, the score has mixed meanings, and global input styling affects every radio. These need correction before surface polish can earn a pass.

Evidence: [supplied HTML, inline CSS and JS](src/catalogslim.html). [Live target](https://catalogslim-waitlist.vercel.app) was unreachable; no CatalogSlim PNG was available when reviewed and local browser launch was blocked. Source defects are identified below; no live/mobile/submission pass is claimed.

## Top 5 quality problems

1. **The success state is broken by contradictory CSS.** `.success{display:none}` remains in force after JS sets `success.hidden=false`. Conversely, `.priestley{display:grid}` can override the browser's ordinary hidden styling when `form.hidden=true`, because there is no `[hidden]` author rule. A successful response therefore cannot reliably produce the intended form-to-confirmation transition.
2. **Every radio receives full-width text-input styling.** `input,textarea{width:100%;padding:.6rem;…}` also targets `.yn input` and `input[name=budget_band]`. Their labels have no proper flex layout or target sizing. Native fieldsets keep default borders and spacing. Textareas also lack an inherited font rule, and the submit button can retain browser button typography.
3. **The score rewards both readiness and the problem being sold.** `syncScore()` adds 10 for every Yes. Q1 rewards catalog size; Q2 rewards “Seen plausible wrong-tool sibling calls”; Q3–Q10 mostly reward good practice. A worse routing experience can increase the total toward `Dieted + measured`. `Catalog Confusion Score` makes high/low direction even less clear.
4. **Page hierarchy looks like an unstyled questionnaire.** `.items` is reused for both benefits and score questions; H2s and paragraph margins have no coherent reset/scale. The score's unstyled `aside` plus `.score-number` retains large default paragraph margins. `.btn` uses exterior margins rather than a CTA layout; `.demand-badge` floats instead of aligning with the wordmark. Pricing has neither a responsive wrapper nor a mobile row design.
5. **Copy exposes an internal positioning debate.** The hero repeats “Search finds; diet disambiguates” and competitor exclusions. `#fit` mentions “product build or checkout on this page.” Required placeholders literally say `situation`, `result`, `budget`, `else`. `UNPROVEN`, `Priestley interview`, `Capture:` and `No SOLVD branding` make the demand test look abandoned.

## Ordered Build fix list

### P0 — release blockers

1. **Fix visibility before changing appearance.** Remove `display:none` from `.success`. Add `[hidden]{display:none!important}` after component rules. Leave `#form-success` hidden initially, and reveal it only on confirmed capture; hide the form then. Give confirmation `role=status` and `tabindex=-1`, move focus to it, and respect reduced motion. Remove the `?submitted`-alone success branch. Test initial, loading, success and error states with intercepted requests so no lead is actually sent.
2. **Make error feedback truthful.** In the submit handler, inspect the provider success body as well as HTTP status. On rejection/network error, retain entered answers, show/announce `#form-error` and re-enable explicit retry. Replace automatic `throwNativeSubmit(form)` after AJAX failure to avoid an ambiguous duplicate POST. Keep the native form action for no-JS submission. Preserve `_honey` rather than deleting it from payloads. Keep recipient, `_subject=CatalogSlim waitlist`, source, score metadata and timestamp unchanged. Apply the [rollup capture-state contract](astra-rollup.md).
3. **Fix all choice controls.** Scope full-width rules to `input[type=email], input[type=url], input[type=text], textarea, select`; add `font:400 1rem/1.4 var(--font-body)` to them. Explicitly size radios to 18px with no padding and `flex:0 0 18px`. Reset fieldsets to border/margin/padding 0, `min-inline-size:0`, and allow legends to wrap. `.yn`: flex, 8px gap; `.yn label` and budget labels: inline-flex/flex, centered vertically, 8px gap, 44px minimum height. Add a `.radio` class to budget labels so styling is scoped. Make selected Yes/No labels filled and retain native checked dots. Add visible 3px focus rings and `--control-border:#70819b`.
4. **Repair score direction while keeping ten checks and the same scoring mechanism.** Use a readiness interpretation throughout: visible name `Catalog Readiness Score`; higher means more practices covered. Keep Yes=10, No=0, thresholds, ten keys and raw Y/N vector. Replace Q1 with `Do you keep an up-to-date inventory of your tools and MCP servers?`; replace Q2 with `Do you keep examples of wrong-tool calls as regression tests?` These are narrowly scoped question corrections so Yes consistently indicates preparation. Keep Q3–Q10 meanings; clarify wording only where needed. Preserve size qualification in who-for copy (`roughly 30+ tools or 3+ MCP servers, especially when agents choose similar tools incorrectly`), not as bonus readiness points. Rename bands in `BANDS`, band legend and result text: `Flat dump` → `Baseline not established`; `Partial diet` → `Some checks covered`; `Fragile routing` → `Most checks covered`; `Dieted + measured` → `Checklist largely covered`. Add `This is a self-assessment, not a measured routing benchmark.` Add hidden `scorecard_version=catalogslim-polish-2026-09-09` so new totals are distinguishable from the older mixed-direction score; do not silently reinterpret old submissions. This repairs the waitlist questionnaire, not the product.

### P1 — bring the page to the shared craft bar

5. **Separate component selectors.** Rename the benefit list class from `.items` to `.bullet-grid` and scope score rules under `#score-items`. Give benefits an H2 `What’s in the pack`, with three 20px H3s. Use a three-column grid at ≥900px, one column below, 16px gaps and 24px padding. Replace floated header badge with a `.header-inner` flex container, 64px minimum height, 16px gap and wrapping. Introduce `.cta-row` around the existing hero anchors; remove `.btn` margins and use the rollup's 48px inline-flex button styles and 16px inherited font. At ≤600px stack full-width CTAs.
6. **Establish a real type/spacing scale.** Use IBM Plex Sans for heading/body, IBM Plex Mono only for scores and prices. Apply the shared H1/H2/H3 scale, paragraph resets, body 16px/1.55, lead 18px/1.55 and 65ch measure. Set hero H1 `max-width:22ch`. Use the rollup's section rhythm and 10px panel/6px control radii. Keep the existing dark base; use lavender `#b8a2ff` as CatalogSlim's accent with `#061024` button text to distinguish it from CompatLab. Keep gradients/shadows minimal.
7. **Give score and form a compact structure.** Add `.scorecard-head` wrapping the existing intro and `.score-readout` around the existing aside contents. Reset `.score-number` margin to 0 and line-height to 1; keep band/progress within 8px. Use a desktop two-column header and mobile stack. Number all ten score rows, with 16px padding, 44px choices and a reliable nested question/answer layout. Partial totals must say partial; completed total shows `/100`, revised band, explanation and CTA together. Center `#waitlist` intro and `.priestley` in the same 720px column; keep 24px field gaps, 96px minimum resizable textareas and all five required questions plus email and budget. Replace one-word placeholders with helpful persistent examples. Keep the score optional for signup.
8. **Show fit and price before the questionnaire.** Move `#fit` between benefits and pricing, split who-for/who-not into two columns above 800px and one on mobile. Add `Early pricing` H2 and shared honest note. Preserve **Audit + diet pack $3,997–$9,997**, **Catalog retain $997–$1,997/mo**, **Golden regression add-on +$1,497** and their current scope. Add table column/row scopes; present labeled stacked offers at ≤600px so long descriptions and ranges stay readable. Keep the 3–5 always-on shortlist concept and complementary relationship to existing tool search; remove repeated defensive explanations.

### P2 — final finishing

9. Add skip link to `#main`, visible keyboard focus, `scroll-margin-top:24px` for this non-sticky header (80px only if Build makes it sticky), and reduced-motion support in both CSS and JS. Add a no-JS score explanation linked to the native form. Preserve native radio keyboard behavior.
10. Replace duplicated inline color styles with component classes. Use sentence-case 14px required/helper/pricing text. Update title and description to the new promise, add matching OG title/description, and verify the existing favicon. Keep product identity and service names; no router UI, dashboard, checkout or metrics widget.
